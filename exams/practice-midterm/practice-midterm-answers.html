Question 1 — WSN Fundamentals and Application Taxonomy14 points

(a) Definitions (4 pts: 1 each definition, 1 each reason)

Mote: a small embedded sensor node — sensor(s), MCU, radio, memory, power supply — that senses, processes and communicates wirelessly.

Sink / gateway: the collection point that gathers the network's data and bridges it to users or other networks (Internet, database, dashboard).

Not "small Wi-Fi": (1) nodes are battery powered with tiny memory/CPU, so energy dominates every design choice; (2) traffic is small, periodic or event-driven measurement data over lossy multi-hop links, attached to a physical environment — it is measurement infrastructure, not general-purpose connectivity.

(c) Control and security (4 pts: 2 explanation, 2 attack)

Monitoring only observes: bad data is annoying. Actuation changes physical state: an incorrect or forged command can cause damage, so authentication, integrity and safe defaults become requirements.

Example attacks on M4: an attacker injects or replays an "open vents" command (spoofing / replay), or jams the channel so the command never arrives.

Question 2 — Mote Hardware and Contiki14 points

(a) Block diagram (5 pts: 0.5 per block, 1.5 flow + dominant blocks)

Sensors → ADC → MCU → Radio → Antenna, with Memory attached to the MCU and the Power subsystem feeding all blocks.

Lifetime is dominated by the radio and the power subsystem.

(b) Contiki process (5 pts: 1 period, 1 window, 1.5 static, 1.5 busy-wait)

"sample" is printed every 5 seconds, visible in Cooja's Mote Output window.

static: protothreads do not keep a stack across PROCESS_WAIT_EVENT_UNTIL; a local (automatic) variable would lose its value while the process is suspended.

No busy wait: the process yields; the MCU can enter a low-power mode until the timer event arrives. A busy loop keeps the CPU active (wasting energy) and blocks the other processes in the cooperative scheduler.

(c) Sky vs Cooja mote (4 pts)

Sky mote: emulates the real MSP430 hardware and CC2420 radio and runs the compiled firmware — closer to hardware timing, memory limits and energy; slower.

Cooja mote: the Contiki code compiled natively and run at software level — much faster, but not hardware-faithful (no real memory/timing constraints).

Choose Sky for labs that measure timing/energy or must match hardware (the course default); Cooja motes for quick logic tests or large networks.

(d) RSSI / LQI / PRR (4 pts)

RSSI: received signal strength (dBm) measured by the radio. LQI: the radio's link-quality indicator, based on the chip error rate of the received frame (802.15.4). PRR: fraction of sent packets that are received.

The transitional region is the distance band between reliable connectivity and no connectivity, where PRR varies widely and unpredictably because of fading, shadowing and noise. Links are asymmetric because nodes differ in transmit power, sensitivity, noise floor and local interference, so A may hear B while B barely hears A.

(c) Dominant term (4 pts)

Listening dominates: 0.215 of 0.221 mA ≈ 97 % of the average current.

Transmissions are negligible; the cost is idle listening. Optimization should reduce listening time — shorter/rarer wake-ups (RDC/MAC design, e.g. ContikiMAC), fewer rendezvous — rather than shrinking packets.

(d) Energest (4 pts)

Energest counts how long (in timer ticks) each component spends in each state: CPU active, LPM, radio transmit, radio listen.

E = Σstate (ticksstate / ticks-per-second) · Istate · V

Currents come from the datasheet (e.g. CC2420, MSP430); V ≈ 3 V for two AA cells.

Question 5 — Medium Access Control20 points

(a) Hidden / exposed terminal (6 pts: 3 each)

Hidden: A and C both send to B. A and C cannot hear each other, so carrier sensing says "free" to both; their frames collide at B.

Exposed: B sends to A while C wants to send to D. C hears B, senses the channel busy and defers — although its transmission to D would not disturb A. Capacity is wasted.

(b) B-MAC vs X-MAC (6 pts: 2 B-MAC, 2 X-MAC, 2 overhearing)

B-MAC: the preamble must be at least as long as the wake-up interval so the receiver surely sees it: the sender transmits for the full 500 ms every time.

X-MAC: the sender repeats short strobes carrying the destination address; the receiver answers with an early ACK as soon as it wakes. With a uniformly random wake-up time the expected wait is Tw/2.

B-MAC: 500 ms · X-MAC: 250 ms on average (500 ms worst case)

Overhearing: a non-target node that wakes up decodes one short strobe, sees it is not the destination and goes back to sleep, instead of listening to a whole long preamble.

Question 6 — 6LoWPAN and RPL Routing14 points

(a) Why adaptation (4 pts)

An 802.15.4 frame carries at most 127 bytes (and much less after MAC headers), while IPv6 has a 40-byte header and requires links to carry 1280-byte packets.

6LoWPAN uses header compression and fragmentation / reassembly.

(b) Fragmentation (5 pts: 2 payload sizes, 3 count)

first: 102 − 4 = 98 → round down to multiple of 8 → 96 bytes

later: 102 − 5 = 97 → 96 bytes; remaining 400 − 96 = 304 = 3·96 + 16

5 fragments carrying 96, 96, 96, 96, 16 bytes

(c) RPL parent choice (5 pts: 2 choice, 1 hop count, 2 ETX reason)

via A: 1.2 + 2.0 = 3.2 · via B: 2.5 + 1.0 = 3.5

X chooses A; path ETX = 3.2

Hop count need not agree: B's path ETX of 1.0 suggests B is one hop from R, so hop count would prefer B (2 hops) over A.

ETX counts expected transmissions including retries, so it reflects real link quality and energy cost; hop count prefers long, lossy links that need many retransmissions.
